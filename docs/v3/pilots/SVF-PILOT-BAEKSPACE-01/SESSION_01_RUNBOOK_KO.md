## 1. 세션 목표

첫 세션에서 알아낼 것은 세 가지뿐이다.

1. 이 사람이 실제로 어떤 문제를 갖고 있는가?
2. 현재 무엇으로 해결하는가?
3. BaekSpace Core 또는 Studio Proxy가 실제 행동을 바꾸는가?

제품을 설명하거나 설득하는 자리가 아니다.

---

## 2. 진행자 금지사항

하지 말 것:

- 기능을 먼저 자랑하기;
- “이 기능 필요하지 않나요?” 질문;
- 사용자가 막히자마자 대신 조작하기;
- Studio의 미래 기능 설명;
- 가격 질문부터 하기;
- 한 명의 반응을 전체시장처럼 해석하기.

---

## 3. 0–10분 — 현재 행동

다음 질문에서 최근 실제 사례를 요청한다.

> “최근 AI 답변 중 따로 남겨둔 것이 하나 있었나요?”

후속:

- 어디에 두셨나요?
- 왜 남겼나요?
- 다시 열어본 적 있나요?
- 다시 봤을 때 무엇을 했나요?

그 다음:

> “요즘 진행 중인데 끝나지 않은 일은 어떤 것이 있나요?”

후속:

- 어디에 기록하나요?
- 오늘 무엇을 할지 어떻게 정하나요?
- 며칠 지나면 맥락을 어떻게 되찾나요?
- 가장 최근에 미룬 이유는 무엇인가요?

이 단계가 끝날 때까지 BaekSpace/Studio 설명 금지.

---

## 4. 10분 — Fit 결정

### Core-fit
실제 문서 저장/재읽기/수정 job이 있음.

→ Core test 진행.

### Studio-fit
복수 프로젝트/Next Action pain이 있음.

→ Studio proxy 진행.

### Both
가능하면 둘 다 진행하되 세션을 길게 끌지 않는다.

권장:

- Core 10–12분;
- Studio 10–12분.

### Neither
제품 테스트를 강요하지 않는다.

간단한 문제 인터뷰로 종료하고 `Neither` 기록.

---

## 5. Core test — 10–12분

진행자 문구:

> “지금 평소에 실제로 다루는 문서 하나를 이 도구에서 한번 사용해 보시겠어요? 제가 기능 설명은 최대한 하지 않고 보고 있겠습니다.”

관찰:

- 첫 행동;
- 문서를 여는 방법 이해;
- 읽기/편집/보관 중 무엇부터 찾는지;
- 기능 탐색;
- 막힘;
- 진행자 도움 횟수;
- privacy/local 이야기를 스스로 하는지;
- 완료 후 “이걸 다시 언제 쓸 것 같은지”가 아니라 **무엇을 했는지**.

막히면:

> “지금 무엇을 하려고 하셨나요?”

를 먼저 묻는다.

바로 사용법을 알려주지 않는다.

---

## 6. Studio proxy — 10–12분

먼저 네 개만 설명한다.

- Project = 여러 행동이 필요한 결과
- Topic = 그 안의 작은 흐름/질문
- Next Action = 실제로 다음에 할 가장 작은 행동
- Today = 지금 할 수 있는 후보 최대 3개

진행자:

> “실제로 지금 진행 중인 것 중 하나를 써보겠습니다.”

참여자가:

1. Project 1–3개 작성;
2. 필요한 Topic만 작성;
3. 각각 Next Action 작성;
4. Today 후보 확인;
5. 하나 선택.

그 다음:

> “이 행동은 실제로 언제 할 수 있나요?”

가능하면 즉시 작은 행동을 시작하게 한다.

중요:

**데이터베이스를 잘 채우는지가 아니라 실제 일이 움직이는지**를 본다.

---

## 7. 마무리 5분

다음만 안내한다.

> “일주일 동안 이것을 꼭 써야 할 필요는 없습니다. 실제 필요할 때만 쓰세요. 저는 나중에 무엇이 일어났는지를 여쭤보겠습니다.”

Core 사용자에게:

- 현재 URL/사용 방법만 제공;
- 사용 횟수 목표를 주지 않는다.

Studio proxy 사용자에게:

- proxy access 제공;
- 매일 입력하라는 지시 금지.

---

## 8. 세션 직후 기록

참여자가 떠난 직후 10분 이내에 `PARTICIPANT_RECORD_TEMPLATE.md` 작성.

특히 분리:

### Observed
실제로 본 것.

### Reported
참여자가 말한 것.

### Inferred
진행자의 해석.

### Hypothesis impact
H1–H7 중 무엇이 조금 강해지거나 약해졌는지.

---

## 9. 첫 3명 이후 규칙

첫 3명 후에는 전략결론을 내리지 않는다.

가능한 것:

- 질문이 너무 유도적인지 수정;
- 사용성 장애로 실험 자체가 불가능한지 확인;
- 기록 포맷 보완.

불가능한 것:

- “Core가 이겼다”;
- “Studio가 이겼다”;
- 성공기준 변경.

질문 문구를 바꾸면 버전 변경으로 기록한다.
