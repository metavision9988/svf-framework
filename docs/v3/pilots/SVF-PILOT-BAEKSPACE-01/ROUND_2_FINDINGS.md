## 2. Decision made

The pilot now selects:

# **D — Dual validation without a second full build**

Meaning:

- test current Core with external users;
- test Studio job through manual/disposable proxy;
- do not build Studio production software yet;
- do not broadly expand Core yet.

This is the first point where SVF has changed not only analysis but the **next action** relative to the frozen baseline.

Frozen baseline preferred:

> B — build Studio S0–S2.

Round 2 selected:

> D — earn the right to build through behavioral evidence.

---

## 3. What counts as success

Not:

- positive comments;
- demo completion;
- requests for more features;
- internal excitement.

Core needs evidence of a repeated real-world job.

Studio needs evidence that:

- the pain exists before the concept;
- Next Action changes real behavior;
- the structure is reused without facilitation.

---

## 4. Important precommitments

### Core

For an exploratory signal:

- at least 5 Core-fit participants;
- ≥3 complete a real target job;
- ≥2 voluntarily return on another day;
- ≥2 identify a concrete substitute/workaround improved by Core.

### Studio

For an exploratory signal:

- at least 5 Studio-fit participants;
- ≥3 describe the underlying pain before seeing Studio;
- ≥3 perform a real Next Action;
- ≥2 voluntarily return and update/use the structure.

These are **pilot decision rules only**.

They are not retention benchmarks or market estimates.

---

## 5. Option C is now constrained

Core expansion is no longer a general option.

It becomes legitimate only when:

> at least two independent Core-fit users hit the same missing capability and that capability blocks completion/repeat use of the target job.

This is a material change from feature-led development.

---

## 6. Studio build gate

Studio S0–S2 is not authorized by:

- concept appeal;
- owner usefulness;
- prototype praise.

It becomes reasonable only if:

1. external pain is independently observed;
2. real Next Actions are performed;
3. voluntary return occurs;
4. software absence, rather than weak job value, is the main remaining friction.

Even then, authorization is only S0–S2.

---

## 7. SVF self-test remains open

A competent simple checklist baseline has been frozen.

SVF is not validated until it shows material incremental value over that simpler method.

Current provisional incremental value:

- action set expanded from A/B/C to D;
- Studio was reclassified from implementation plan to hypothesis;
- explicit anti-hindsight triggers now exist;
- broad C expansion was converted into blocker-evidence-only authorization.

These are meaningful changes, but the burden of the full SVF artifact set may still be too high.
